🚀 Démarrage rapide

De zéro à un assistant fonctionnel en une commande.

Prérequis

  • Une machine Linux (ou macOS) avec au moins 8 Go de RAM et quelques Go d'espace disque libre (davantage selon le modèle d'IA choisi).
  • Docker n'est pas nécessaire au préalable : install.sh l'installe automatiquement sur Debian/Ubuntu s'il est absent.

Installation

cd assistant-ia
./install.sh

Le script installe Docker si besoin, construit les images, télécharge un modèle d'IA adapté à la machine, démarre tous les services, puis crée le compte administrateur initial.

Premier accès

  • Utilisateurs : http://<adresse-du-serveur>:3000
  • Administration : http://<adresse-du-serveur>:3000/admin
  • Les identifiants du compte administrateur initial sont affichés une seule fois à la fin de l'installation.

💬 Utilisation au quotidien

Ce que voient les utilisateurs et ce que gèrent les comptes d'administration.

  • La page d'accueil permet de poser une question en langage naturel ; l'assistant répond en s'appuyant sur les documents indexés.
  • Les échanges ne sont pas conservés après fermeture de la page (confidentialité).
  • Un pouce 👍/👎 sur chaque réponse aide l'assistant à s'améliorer au fil du temps.
  • Une pièce jointe (texte ou PDF) peut être envoyée par un utilisateur pour enrichir le contexte d'une question ponctuelle — l'administrateur peut désactiver cette possibilité depuis l'onglet Pièces jointes.
  • Quand l'assistant n'a ni document interne ni connaissance générale fiable pour répondre, il le dit clairement ("je ne sais pas...") et propose un lien de recherche externe, plutôt que d'inventer une réponse ou de suggérer systématiquement une recherche Internet.

🗂️ Administration

Accessible depuis /admin, réservée aux comptes autorisés.

Documents

Ajoutez vos fichiers (PDF, Word, Excel, HTML...) depuis l'onglet Documents : ils sont automatiquement découpés, vectorisés et indexés pour la recherche.

Modèles

Changez le modèle de conversation depuis l'onglet Modèles. Les modèles Mistral AI (Mistral, Mixtral, Codestral, Ministral, Devstral, Pixtral, Magistral) sont repérés par un petit drapeau français.

Pièces jointes

L'onglet Pièces jointes permet d'activer ou de désactiver globalement la possibilité pour les utilisateurs de joindre un fichier dans le chat, et de trier (conserver ou supprimer) les fichiers déjà envoyés.

Export et déploiement

La note de version se pré-remplit automatiquement (date, heure, numéro de version) et reste enregistrée dans le navigateur tant que la version n'est pas publiée — vous n'avez jamais besoin d'écrire quelque chose à la main pour publier.

Sauvegarde

Les données vivent dans backend/data (base) et backend/uploads (fichiers). Pensez à les sauvegarder régulièrement si l'instance contient des documents importants.

🩺 Dépannage

Les situations rencontrées en production, classées par thème, avec leur correctif exact.

Premier réflexe : lancez ./doctor.sh. Il diagnostique l'installation de bout en bout et corrige automatiquement la plupart des cas ci-dessous (Docker, groupe docker, CRLF, permissions, dossiers manquants, port occupé, secrets, conteneurs arrêtés, modèles absents, écart de version après mise à jour, cache du canal de mise à jour…). ./doctor.sh --check-only se contente d'auditer sans rien modifier.

Installation & Docker

« Ollama n'a pas répondu dans le délai imparti » / téléchargement de modèle qui échoue

Cause la plus fréquente : espace disque insuffisant pour télécharger le modèle. install.sh et doctor.sh nettoient automatiquement le cache Docker et s'arrêtent tôt avec un message clair si l'espace restant est trop faible (moins de 2 Go). Vérifiez avec df -h et lsblk : un disque plus grand existe peut-être mais n'est pas monté sur la bonne partition. Il faut au moins ~4–8 Go libres selon le modèle choisi.

« permission denied » sur /var/run/docker.sock

L'utilisateur vient d'être ajouté au groupe docker mais la session shell ne l'a pas encore pris en compte. install.sh et doctor.sh tentent de réactiver le groupe à la volée (newgrp / sg / sudo -g) ; en dernier recours, déconnectez-vous puis reconnectez-vous (ou ssh à nouveau).

« docker: 'compose' is not a docker command » / plugin compose introuvable

Seul docker-compose v1 (l'ancien binaire) est présent ; le projet exige le plugin Docker Compose v2 (docker compose, sans tiret). Installez le paquet docker-compose-plugin (ou réinstallez Docker via le script officiel get.docker.com, ce que fait install.sh).

Le daemon Docker ne répond pas

Sur Linux : sudo systemctl start docker (et sudo systemctl enable docker pour le démarrage automatique). Sur macOS/Windows : lancez Docker Desktop et attendez qu'il soit prêt. doctor.sh tente le redémarrage du service automatiquement.

Scripts & permissions de fichiers

« env: '…\r': No such file or directory » ou « env: opérande supplémentaire »

Les scripts ont des fins de ligne Windows (CRLF), généralement après un transfert depuis Windows ou un éditeur mal configuré. Corrigez :

sed -i 's/\r$//' *.sh

doctor.sh détecte et corrige ce cas.

« Permission denied » en lançant un script / fichiers appartenant à root

L'archive a été extraite avec sudo, ou une mise à jour a été lancée depuis l'interface web (processus root). Reprenez la propriété et le bit exécutable :

sudo chown -R "$(id -un):$(id -gn)" ~/assistant-ia
chmod +x ~/assistant-ia/*.sh

Des fichiers possédés par root font aussi échouer git pull et ./update.sh.

« node : commande introuvable »

Node.js n'est pas requis sur l'hôte : les scripts appellent Node via le conteneur assistant-ia-updater. Si ce message apparaît quand même, la copie du projet est ancienne — redéployez la dernière release.

« rsync » ou « sha256sum » introuvable

L'installation de base fonctionne sans eux, mais ./update.sh et ./install.sh --vX.Y.Z en ont besoin (synchronisation des fichiers et vérification d'intégrité des archives). Installez-les : sudo apt install rsync coreutils.

Réseau & accès

Le port 3000 n'est pas accessible depuis le réseau

Si un pare-feu UFW est actif, install.sh ouvre le port automatiquement. Sinon, manuellement :

sudo ufw allow 3000/tcp

Sur un serveur distant (cloud), pensez aussi au groupe de sécurité / pare-feu du fournisseur.

« Le port 3000 est déjà utilisé par un autre processus »

Identifiez le processus : sudo lsof -i :3000. Arrêtez-le, ou changez SERVER_PORT dans .env puis ./restart.sh.

Administration accessible sans HTTPS depuis Internet

Pour une exposition publique : placez l'instance derrière un reverse proxy HTTPS (nginx, Caddy, Traefik), passez COOKIE_SECURE=true dans .env, et restreignez /admin via ADMIN_ACCESS_MODE=local ou un pare-feu.

Configuration & secrets

« Fichier .env absent » / secrets trop courts ou d'exemple

install.sh copie .env.example vers .env et génère les secrets (JWT_SECRET, CONFIG_ENCRYPTION_KEY). Si .env a été perdu ou contient encore des valeurs d'exemple, relancez ./doctor.sh : il régénère les secrets manquants. PROJECT_WORKSPACE_DIR doit pointer sur le dossier réel du projet.

Un fichier JSON commence par un caractère invisible (BOM) et « JSON.parse échoue »

version.json, update.config.json ou branding.json a été réenregistré en UTF-8 avec BOM (souvent par un éditeur Windows). Réenregistrez le fichier en UTF-8 sans BOM, ou : sed -i '1s/^\xEF\xBB\xBF//' fichier.json.

Mises à jour

Une mise à jour lancée dans le terminal n'apparaît pas dans l'admin web

Corrigé en v1.021 : la page d'administration se rafraîchit désormais automatiquement en arrière-plan et au retour sur l'onglet. Sur une version antérieure, rechargez la page manuellement.

La version affichée n'a pas changé après ./update.sh (conteneurs pas reconstruits)

version.json sur le disque est plus récent que l'image Docker du backend : les fichiers ont été synchronisés mais l'image n'a pas été reconstruite. Terminez avec ./update.sh (il reconstruit le backend), ou lancez ./doctor.sh qui le détecte et reconstruit automatiquement. En dernier recours, revenez en arrière depuis l'onglet Mises à jour de l'administration.

Toute mise à jour ou rollback échoue avec le code 125

Le conteneur assistant-ia-updater ne sait pas invoquer docker compose. Reconstruisez-le : docker compose up -d --build updater. doctor.sh tente cette reconstruction automatiquement ; sinon vérifiez docker logs --tail 50 assistant-ia-updater.

« Quota API GitHub atteint » (403) à la vérification de mise à jour

Sur une IP partagée (NAT de campus, hébergement mutualisé), le quota GitHub non authentifié (60 requêtes/h) peut être épuisé par d'autres. Depuis v1.1.0, l'updater met la liste des releases en cache et plafonne ses appels à ~10/jour ; le fichier .update-release-cache.json est préservé lors des mises à jour. En attendant la fin de la fenêtre de quota, ./update.sh se rabat automatiquement sur une reconstruction locale. Démarrez le conteneur updater pour bénéficier du cache.

« Dépôt de mise à jour introuvable » (404) ou « aucune release publiée »

Vérifiez le champ repository de update.config.json (format propriétaire/dépôt) et qu'il pointe sur un dépôt public avec au moins une release GitHub publiée (voir docs/GITHUB_RELEASES.md). Sans release, seule la reconstruction locale fonctionne.

« La dernière mise à jour a échoué après avoir synchronisé les fichiers »

Une mise à jour distante s'est interrompue après la copie des fichiers mais avant la reconstruction. Relancez ./update.sh pour la terminer, ou restaurez le point de sauvegarde indiqué depuis l'onglet Mises à jour de l'administration. Assurez-vous d'avoir au moins ~300 Mo libres (archive + extraction + sauvegarde de rollback).

Mise à jour derrière un proxy d'entreprise

Si un proxy sortant est configuré, docker-compose.yml doit passer NODE_USE_ENV_PROXY=1 au conteneur updater, sinon la vérification des releases échoue silencieusement. doctor.sh signale ce cas.

Services & données

Un conteneur redémarre en boucle / ne démarre pas

Consultez les journaux du service concerné : docker compose logs -f backend (ou ollama, chromadb, redis, updater). doctor.sh teste la santé de chaque service (Redis PING, heartbeat ChromaDB, /api/health du backend) et tente un redémarrage ciblé.

Un modèle Ollama est absent après installation

Téléchargez-le manuellement : docker exec assistant-ia-ollama ollama pull <nom-du-modèle>. Vérifiez l'espace disque et l'orthographe exacte du modèle. doctor.sh propose de retélécharger les modèles manquants.

Base de données SQLite corrompue ou en-tête invalide

Le fichier backend/data/*.sqlite n'a pas une en-tête SQLite valide (coupure d'alimentation, disque plein pendant une écriture). Restaurez la dernière sauvegarde de backend/data. Sans sauvegarde, ./reset.sh repart d'une base vide (perte de l'historique et de la configuration).

Un compte initial utilise encore un mot de passe prévisible

Changez-le immédiatement depuis l'administration, ou régénérez un mot de passe référent : cd backend && npm run password:reset-teacher (force le changement à la prochaine connexion).
